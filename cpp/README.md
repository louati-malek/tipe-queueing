# C++ simulator

A C++17 implementation of the M/M/c/K discrete-event simulator, with the same logic as
`queueing/simulation.py`. Python keeps the theory, analysis and plots; C++ does the heavy simulation.

```
cpp/
├── include/mmck.hpp     # Params, Result, simulate()
├── src/mmck.cpp         # event loop: min-heap of busy servers, FIFO deque, time-weighted statistics
├── src/main.cpp         # command line: runs replications, prints CSV
├── tests/test_mmck.cpp  # checks against Erlang C, M/M/c/K blocking and Little's law
└── CMakeLists.txt
```

## Build

You need CMake and a C++17 compiler.

**Windows:** install either "Build Tools for Visual Studio" (C++ workload) or MinGW-w64 (e.g. via MSYS2).
In VS Code, the CMake Tools extension can configure and build with one click.

```bash
cmake -S cpp -B cpp/build
cmake --build cpp/build --config Release
ctest --test-dir cpp/build -C Release --output-on-failure
```

## Use

```bash
# 30 replications of the original "saturated" TIPE scenario with 3 servers
cpp/build/mmck_sim --lam 0.004 --mu 0.0033333 --c 3 --reps 30 --seed 100
```

Output is one CSV row per replication: `rep,Wq,W,L,Lq,p_block,served,events,seconds`.
From Python, `queueing.cpp_bridge.run_cpp(...)` calls the binary and parses the output.

## Results

`python -m experiments.cpp_benchmark` compares C++ with theory and with the Python simulator.
See `results/cpp_benchmark.md`: both agree with theory, and C++ processes about 20–25× more events
per second (24× on the latest run; the ratio depends on the machine).

## Possible extension: time-varying arrivals

Real traffic is not constant: it peaks during office hours. A natural extension is a
**non-homogeneous Poisson process** with rate λ(t), generated by *thinning* (Lewis–Shedler):

1. Pick λ_max ≥ λ(t) for all t.
2. Generate candidate arrivals at rate λ_max (exponential gaps).
3. Accept a candidate at time t with probability λ(t) / λ_max; otherwise discard it.

In `mmck.cpp`, this only changes how `next_arr` is computed: a `std::function<double(double)>` rate in
`Params`, with the constant rate as the default. With λ(t) constant, results must match the existing ones.
